# Omarchy research: Hyprland implementation, agent harness, and Fedora portability

Research date: 2026-09-16. Author of record: research session on branch `task/f6300d35`.

## 0. Scope, sources, and the revision analyzed

This document is built from primary sources, in this order of authority:

1. The Omarchy source tree itself. `basecamp/omarchy` now redirects to [`omacom/omarchy`](https://github.com/omacom/omarchy); the default branch is `quattro`. A shallow clone at commit `2fbac0c` (2026-09-15, `version` file `4.0.0.alpha`, HEAD commit "Merge pull request #11934 from omacom/claude-browser-extension") is the main reference, referred to below as **v4** or **quattro**. Every repo path in this document links to `https://github.com/omacom/omarchy/blob/quattro/<path>`.
2. Tag [`v4.0.4`](https://github.com/omacom/omarchy/tree/v4.0.4) (2026-09-15, the current stable release) and tag [`v3.8.4`](https://github.com/omacom/omarchy/tree/v3.8.4) (2026-07-21, the last release of the pre-Quattro "classic" generation), fetched for comparison. Where the two generations differ materially, both are described, because the classic stack is far closer to what a Fedora Hyprland setup normally looks like.
3. The Omarchy packaging repo [`omacom/omarchy-pkgs`](https://github.com/omacom/omarchy-pkgs) (the PKGBUILDs that turn the tree into the `omarchy` and `omarchy-settings` Arch packages).
4. The published manual at https://omarchy.org/manual/, whose source is the repo's [`manual/`](https://github.com/omacom/omarchy/tree/quattro/manual) directory (the AI chapter is [`manual/17-ai.md`](https://github.com/omacom/omarchy/blob/quattro/manual/17-ai.md) = https://omarchy.org/manual/ai/).
5. DHH's own writing at https://world.hey.com/dhh and the GitHub release notes for v4.0.0 "Quattro" and v4.0.4.
6. Fedora 44 host queries (`dnf repoquery`) and the COPR API, run on the machine this research was done on.

Two framing facts shape everything below:

- **Quattro (v4.0.0, 2026-08-14) was a rewrite of the desktop layer.** The release notes state that "Waybar, Walker, Mako, SwayOSD, hyprlock, hypridle, swaybg, and polkit-gnome are all gone, replaced by one coherent, fully-themed, IPC-scriptable shell" built on Quickshell, and that the Hyprland configuration was "converted to Lua for full 0.56 compatibility" ([release v4.0.0](https://github.com/omacom/omarchy/releases/tag/v4.0.0)). v3.8.4 is the last release with the conventional waybar/walker/mako/hyprlock/hypridle stack.
- **Quattro also moved Omarchy from a git checkout in `~/.local/share/omarchy` to system packages.** `$OMARCHY_PATH` now defaults to `/usr/share/omarchy`, user defaults are seeded through `/etc/skel`, and the desktop is delivered by two pacman packages, `omarchy` and `omarchy-settings` ([`docs/file-layout.md`](https://github.com/omacom/omarchy/blob/quattro/docs/file-layout.md), [`omarchy-pkgs/pkgbuilds/omarchy/PKGBUILD`](https://github.com/omacom/omarchy-pkgs/blob/master/pkgbuilds/omarchy/PKGBUILD)).

## 1. The Hyprland implementation

### 1.1 Compositor packaging: which Hyprland, from where

Omarchy installs plain `hyprland` from its package list ([`install/omarchy-base.packages`](https://github.com/omacom/omarchy/blob/quattro/install/omarchy-base.packages)), together with `hyprland-guiutils`, `hyprland-preview-share-picker`, `hyprpicker`, `hyprsunset`, `xdg-desktop-portal-hyprland`, `xdg-desktop-portal-gtk`, `uwsm`, `sddm`, and `quickshell`. Package resolution goes through Omarchy's own pacman configuration: [`default/pacman/pacman-stable.conf`](https://github.com/omacom/omarchy/blob/quattro/default/pacman/pacman-stable.conf) lists `[core]`, `[extra]`, `[multilib]` and then an `[omarchy]` repo at `https://pkgs.omarchy.org/stable/$arch`. The Arch repos themselves are served from Omarchy's own mirror, which the manual says "runs one month behind the latest" ([manual/updates](https://omarchy.org/manual/updates/)).

The Hyprland recipe in `omarchy-pkgs` ([`pkgbuilds/hyprland/PKGBUILD`](https://github.com/omacom/omarchy-pkgs/blob/master/pkgbuilds/hyprland/PKGBUILD)) is a copy of the Arch `extra` recipe at `pkgver=0.56.2`, restricted to `arch=(aarch64)`; its metadata marks it `release_ring: fast` with an upstream watch on `hyprwm/Hyprland` tags. So on x86_64, Hyprland is the stock Arch `extra/hyprland 0.56.2` build, and Omarchy only rebuilds it for its Apple Silicon port. The recipe's `depends` list includes `lua`, which is the runtime dependency the Lua configuration needs. The Omarchy tree carries no version guard: the Lua API (`hl.config`, `hl.bind`, `hl.window_rule`, `hl.on`, `hl.dsp.*`, `hl.animation`, `hl.monitor`, `hl.gesture`) is used unconditionally, and the only version string in the tree is a test comment, "Measured on Hyprland 0.56.2" ([`test/shell.d/hyprland-qconsole-test.sh`](https://github.com/omacom/omarchy/blob/quattro/test/shell.d/hyprland-qconsole-test.sh)). Treat **Hyprland >= 0.56** as the effective floor for the v4 configuration.

Quickshell is the other load-bearing dependency. Arch `extra` ships `quickshell 0.3.1`; `omarchy-pkgs` additionally carries a `quickshell-git` recipe pinned to a specific upstream commit with `sync: false` ([`pkgbuilds/quickshell-git/`](https://github.com/omacom/omarchy-pkgs/tree/master/pkgbuilds/quickshell-git)), and the `omacom` org maintains a tracking fork of Quickshell. The `omarchy` package hard-depends on `hyprland`, `quickshell`, `uwsm`, `sddm`, `xdg-desktop-portal-hyprland`, `wireplumber`, `pipewire`, `gnome-keyring`, `gum`, `jq`, `git`, `perl`, `fakeroot`, `pacman-contrib`, `ttf-jetbrains-mono-nerd-basic` and, on x86_64, `limine`, `limine-mkinitcpio-hook`, `limine-snapper-sync`, `snapper` ([`pkgbuilds/omarchy/PKGBUILD`](https://github.com/omacom/omarchy-pkgs/blob/master/pkgbuilds/omarchy/PKGBUILD)).

### 1.2 Session start: SDDM, uwsm, and the autostart chain

- **Display manager.** SDDM is enabled in [`install/config/enable-services.sh`](https://github.com/omacom/omarchy/blob/quattro/install/config/enable-services.sh) alongside NetworkManager, cups, avahi, docker.socket, systemd-resolved, power-profiles-daemon and systemd-oomd. The SDDM theme ships from [`default/sddm/`](https://github.com/omacom/omarchy/tree/quattro/default/sddm). [`install/login/sddm.sh`](https://github.com/omacom/omarchy/blob/quattro/install/login/sddm.sh) strips `pam_gnome_keyring.so` from `/etc/pam.d/sddm` so that a password login does not create an encrypted keyring that would conflict with Omarchy's passwordless default keyring.
- **Session entry.** One wayland-session file, [`default/wayland-sessions/omarchy.desktop`](https://github.com/omacom/omarchy/blob/quattro/default/wayland-sessions/omarchy.desktop): `Exec=uwsm start -g -1 -e -D Hyprland hyprland.desktop`. uwsm puts Hyprland under systemd's `graphical-session.target`, and every Omarchy launcher (`omarchy-launch-terminal`, `omarchy-launch-tui`, `omarchy-launch-webapp`) runs apps through `uwsm-app` so they land in their own systemd scopes. `OMARCHY_PATH` reaches the session through [`default/uwsm/env.d/10-omarchy`](https://github.com/omacom/omarchy/blob/quattro/default/uwsm/env.d/10-omarchy), installed to `/usr/share/uwsm/env.d/`.
- **Autostart.** [`default/hypr/autostart.lua`](https://github.com/omacom/omarchy/blob/quattro/default/hypr/autostart.lua) hooks `hyprland.start` and runs, in order: `systemctl --user import-environment`, `dbus-update-activation-environment --systemd --all`, `omarchy-launch-shell` (the Quickshell desktop), `omarchy-provision-first-run`, `omarchy-powerprofiles-init`, `omarchy-hyprland-monitor-watch`, `udiskie --automount`, and the `post-boot` hook. Compare v3.8.4's [`default/hypr/autostart.conf`](https://github.com/omacom/omarchy/blob/v3.8.4/default/hypr/autostart.conf), which `exec-once`d `hypridle`, `mako`, `waybar`, `fcitx5`, `swaybg -i ~/.config/omarchy/current/background -m fill`, and `polkit-gnome-authentication-agent-1` as separate processes.
- **User units.** First login runs [`install/user/first-run/enable-user-units.sh`](https://github.com/omacom/omarchy/blob/quattro/install/user/first-run/enable-user-units.sh), enabling `bt-agent`, `omarchy-recover-internal-monitor`, `omarchy-sleep-lock`, `omarchy-migrate-notify`, `omarchy-fcitx5`, and `omarchy-crash-watch` from [`default/systemd/user/`](https://github.com/omacom/omarchy/tree/quattro/default/systemd/user).

### 1.3 The Hyprland configuration itself (v4, Lua)

Hyprland reads `~/.config/hypr/hyprland.lua`. The shipped copy is [`config/hypr/hyprland.lua`](https://github.com/omacom/omarchy/blob/quattro/config/hypr/hyprland.lua), seeded via `/etc/skel` and kept as a resync source at `/usr/share/omarchy/config/hypr/`. It is 29 lines and does four things:

```lua
dofile((os.getenv("OMARCHY_PATH") or "/usr/share/omarchy") .. "/default/hypr/bootstrap.lua")
require("default.hypr.omarchy")          -- Omarchy defaults
require("hypr.monitors"); require("hypr.input"); require("hypr.bindings")
require("hypr.looknfeel"); require("hypr.autostart")   -- user overrides, ~/.config/hypr/*.lua
require("default.hypr.toggles")          -- runtime toggle flags
```

- [`default/hypr/bootstrap.lua`](https://github.com/omacom/omarchy/blob/quattro/default/hypr/bootstrap.lua) clears cached `default.hypr.*`, `hypr.*` and `omarchy.current.theme.*` modules (so `hyprctl reload` re-executes them) and sets `package.path` to search `~/.local/state/?.lua`, then `~/.config/?.lua`, then `$OMARCHY_PATH/?.lua`. That ordering is the whole override model: `require("hypr.bindings")` resolves to `~/.config/hypr/bindings.lua`, `require("default.hypr.omarchy")` to `/usr/share/omarchy/default/hypr/omarchy.lua`, and `require_optional("omarchy.current.theme.hyprland")` to the active theme's generated file under `~/.local/state/omarchy/current/theme/hyprland.lua`.
- [`default/hypr/omarchy.lua`](https://github.com/omacom/omarchy/blob/quattro/default/hypr/omarchy.lua) is the real default config. It requires [`helpers.lua`](https://github.com/omacom/omarchy/blob/quattro/default/hypr/helpers.lua) (the `o.bind`, `o.rebind`, `o.window`, `o.launch` helpers), the six binding files under [`default/hypr/bindings/`](https://github.com/omacom/omarchy/tree/quattro/default/hypr/bindings), then [`envs.lua`](https://github.com/omacom/omarchy/blob/quattro/default/hypr/envs.lua), [`looknfeel.lua`](https://github.com/omacom/omarchy/blob/quattro/default/hypr/looknfeel.lua), [`qconsole.lua`](https://github.com/omacom/omarchy/blob/quattro/default/hypr/qconsole.lua), [`input.lua`](https://github.com/omacom/omarchy/blob/quattro/default/hypr/input.lua), [`windows.lua`](https://github.com/omacom/omarchy/blob/quattro/default/hypr/windows.lua) (which pulls every file in [`default/hypr/apps/`](https://github.com/omacom/omarchy/tree/quattro/default/hypr/apps)), and finally the theme's optional Hyprland module. Setting the global `omarchy_default_bindings = false` before the require drops all default bindings; `omarchy_preinstalled_bindings = false` drops only the app/webapp launch bindings.
- The user-facing override files installed to `~/.config/hypr/` are [`bindings.lua`](https://github.com/omacom/omarchy/blob/quattro/config/hypr/bindings.lua), [`looknfeel.lua`](https://github.com/omacom/omarchy/blob/quattro/config/hypr/looknfeel.lua), [`input.lua`](https://github.com/omacom/omarchy/blob/quattro/config/hypr/input.lua), [`monitors.lua`](https://github.com/omacom/omarchy/blob/quattro/config/hypr/monitors.lua), [`autostart.lua`](https://github.com/omacom/omarchy/blob/quattro/config/hypr/autostart.lua), plus [`hyprsunset.conf`](https://github.com/omacom/omarchy/blob/quattro/config/hypr/hyprsunset.conf) and [`xdph.conf`](https://github.com/omacom/omarchy/blob/quattro/config/hypr/xdph.conf), which stay in Hyprland's native config language because they configure external daemons. [`config/hypr/.luarc.json`](https://github.com/omacom/omarchy/blob/quattro/config/hypr/.luarc.json) points `lua-language-server` at `/usr/share/hypr/stubs` and declares the `hl` and `o` globals.
- Runtime toggles: [`bin/omarchy-hyprland-toggle`](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-hyprland-toggle) copies a flag module from [`default/hypr/toggles/`](https://github.com/omacom/omarchy/tree/quattro/default/hypr/toggles) into `~/.local/state/omarchy/toggles/hypr/` (or removes it) and runs `hyprctl reload`; [`default/hypr/toggles.lua`](https://github.com/omacom/omarchy/blob/quattro/default/hypr/toggles.lua) loads whatever is there. Per-workspace layouts chosen with `Super+L` persist the same way through [`workspace-layouts.lua`](https://github.com/omacom/omarchy/blob/quattro/default/hypr/workspace-layouts.lua).
- Resetting: [`bin/omarchy-refresh-hyprland`](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-refresh-hyprland) re-copies each shipped file into `~/.config/hypr/` with a timestamped `.bak`; [`bin/omarchy-reinstall-configs`](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-reinstall-configs) replays all of `/etc/skel` over `$HOME`.

**Look-and-feel defaults** ([`default/hypr/looknfeel.lua`](https://github.com/omacom/omarchy/blob/quattro/default/hypr/looknfeel.lua)): `gaps_in 5`, `gaps_out 10`, `border_size 2`, active border a 45-degree `33ccff -> 00ff99` gradient (themes override this), `rounding 0`, shadows **off**, blur **off** (v3.8.4 had both on), `layout dwindle` with `preserve_split` and `force_split 2`, scrolling layout `column_width 0.49`, animations on with named bezier curves, `disable_hyprland_logo`, `focus_on_activate`, `allow_session_lock_restore`. Window opacity `0.985 0.96` is applied to everything tagged `default-opacity` by [`windows.lua`](https://github.com/omacom/omarchy/blob/quattro/default/hypr/windows.lua); media apps opt out in [`apps/system.lua`](https://github.com/omacom/omarchy/blob/quattro/default/hypr/apps/system.lua). [`qconsole.lua`](https://github.com/omacom/omarchy/blob/quattro/default/hypr/qconsole.lua) turns the `special:scratchpad` workspace into a Quake-style drop-down whose `on_created_empty` command is `omarchy-agent`, so an empty scratchpad opens the default coding agent.

**Input** ([`default/hypr/input.lua`](https://github.com/omacom/omarchy/blob/quattro/default/hypr/input.lua)): reads `XKBLAYOUT`/`XKBVARIANT` from `/etc/vconsole.conf` on every load, `kb_options compose:caps,shift:both_capslock_cancel`, prepends `us,` and adds `grp:alts_toggle` for non-Latin layouts so `Super+W` stays reachable, `repeat_rate 40`, `repeat_delay 250`, `numlock_by_default`, touchpad `natural_scroll false`, `clickfinger_behavior`, `scroll_factor 0.4`.

**Environment** ([`default/hypr/envs.lua`](https://github.com/omacom/omarchy/blob/quattro/default/hypr/envs.lua)): forces Wayland for GTK, Qt, Firefox and Electron, sets `XDG_CURRENT_DESKTOP=Hyprland`, `QT_QPA_PLATFORMTHEME=gtk3`, cursor size 24, re-asserts `OMARCHY_PATH` and puts `$OMARCHY_PATH/bin` first on `PATH`, and sources [`nvidia.lua`](https://github.com/omacom/omarchy/blob/quattro/default/hypr/nvidia.lua), which sets `NVD_BACKEND`/`LIBVA_DRIVER_NAME`/`__GLX_VENDOR_LIBRARY_NAME` from cached sysfs detectors rather than `lspci` (which would wake a suspended hybrid GPU).

### 1.5 The ecosystem around the compositor

The distinctive v4 decision is that every "ecosystem" role except the capture tools, the terminal screensaver, the night-light daemon and the portal runs inside one Quickshell process, `omarchy-shell`, launched by [`bin/omarchy-launch-shell`](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-launch-shell) as `quickshell -n -p "$OMARCHY_PATH/shell"` under `systemd-cat` with a crash/relaunch loop. The entry point is [`shell/shell.qml`](https://github.com/omacom/omarchy/blob/quattro/shell/shell.qml); each role is a plugin directory under [`shell/plugins/`](https://github.com/omacom/omarchy/tree/quattro/shell/plugins) with a `manifest.json` declaring one or more `kinds` (`bar`, `bar-widget`, `panel`, `overlay`, `menu`, `service`). Scripts talk to it through [`bin/omarchy-shell`](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-shell), a wrapper over `qs ipc call`. Architecture references: [`docs/omarchy-shell.md`](https://github.com/omacom/omarchy/blob/quattro/docs/omarchy-shell.md), [`docs/menu.md`](https://github.com/omacom/omarchy/blob/quattro/docs/menu.md), [`docs/notifications.md`](https://github.com/omacom/omarchy/blob/quattro/docs/notifications.md), [`shell/README.md`](https://github.com/omacom/omarchy/blob/quattro/shell/README.md).

### 1.6 Theming

Themes are directories under [`themes/`](https://github.com/omacom/omarchy/tree/quattro/themes) (22 built in) or `~/.config/omarchy/themes/<name>/`. Source of truth is `colors.toml` (a 24-color palette since v4); everything else is rendered from templates in [`default/themed/`](https://github.com/omacom/omarchy/tree/quattro/default/themed) by [`bin/omarchy-theme-set-templates`](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-theme-set-templates). Reference: [`docs/theming.md`](https://github.com/omacom/omarchy/blob/quattro/docs/theming.md), [`manual/43-making-your-own-theme.md`](https://github.com/omacom/omarchy/blob/quattro/manual/43-making-your-own-theme.md).

## 2. The default agent harness and skills

### 2.1 What "default agent" means in Omarchy

Omarchy does not bundle an agent runtime of its own, and since v4 it does not preinstall one either. What it ships is the **substrate an agent runs on**: a uniform install path, a uniform launch path with per-harness unattended-mode flags, a skill fan-out to every harness's skill directory, a terminal session layer built for agents (herdr), a crash-to-agent pipeline, usage telemetry in the bar, and theme sync into the agents. The user then picks one harness, and Omarchy treats that pick the way it treats the default browser or terminal: a `Setup > Defaults` choice with a keybinding and menu entries behind it. The manual's own words: "Omarchy treats AI coding agents as first-class citizens, but it doesn't pick a favorite for you" ([`manual/17-ai.md`](https://github.com/omacom/omarchy/blob/quattro/manual/17-ai.md)). omarchy.org now bills the distribution as "Beautiful, fun & agentic Linux" and "the malleable OS for the age of agents".

This is a change from v3. At tag v3.8.4, `claude-code` was in the base package list ([`install/omarchy-base.packages`](https://github.com/omacom/omarchy/blob/v3.8.4/install/omarchy-base.packages) line 19), the `cx` alias ran `claude --permission-mode bypassPermissions` ([`default/bash/aliases`](https://github.com/omacom/omarchy/blob/v3.8.4/default/bash/aliases)), and one flat skill was symlinked into four directories by [`install/config/omarchy-ai-skill.sh`](https://github.com/omacom/omarchy/blob/v3.8.4/install/config/omarchy-ai-skill.sh). In effect Claude Code was the de-facto default; v4 generalized that into the harness-neutral layer below, all of it landing in the v3.8.4 to v4.0.4 window (21 files, about 3,300 lines added).

### 2.2 Harness inventory and the lazy install path

[`install/user/mise.sh`](https://github.com/omacom/omarchy/blob/quattro/install/user/mise.sh) creates a stub for each harness with [`bin/omarchy-mise-install`](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-mise-install), which writes a three-line wrapper to `~/.local/bin/<command>`:

```bash
#!/bin/bash
export MISE_MINIMUM_RELEASE_AGE=0
mise use -g --quiet "$package" || exit 1
exec mise x "$package" -- "$bin" "$@"
```

Nothing is downloaded until the command is first run. The roster at HEAD: `claude`, `codex`, `opencode`, `agy` (Google Antigravity, renamed from `gemini` after v4.0.4), `copilot`, `crush`, `grok` (`npm:@xai-official/grok`), `pi`, `omp` (`github:can1357/oh-my-pi`), `ori` (`github:OpenRouterLabs/ori-releases`, added after v4.0.4), `hermes`, `muse` (Meta, via mise's HTTP backend), `cursor-agent`. Two are not plain mise stubs: Hermes has [`bin/omarchy-install-hermes-cli`](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-install-hermes-cli) (pipx backend with a pinned Python, and a hand-over rule when Hermes Desktop is installed), and OpenClaw is the `openclaw` pacman package ([`bin/omarchy-install-openclaw-cli`](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-install-openclaw-cli)). Desktop AI apps (ChatGPT, Claude desktop, Hermes Desktop, OpenClaw, Perplexity, LM Studio, Ollama) are separate `omarchy-install-ai-*` scripts that call `omarchy-pkg-add` on Arch packages.

### 2.3 Choosing and launching the default agent

- **Selection**: [`bin/omarchy-default-agent`](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-default-agent) resolves aliases (`claude-code`, `gemini`, `cursor`, ...), installs the harness if missing (in a floating terminal with Omarchy's logo/done presentation via [`bin/omarchy-launch-floating-terminal-with-presentation`](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-launch-floating-terminal-with-presentation)), writes the bare id to `~/.config/omarchy/defaults/agent`, and for `claude` additionally runs [`bin/omarchy-install-chromium-claude`](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-install-chromium-claude) to register the Claude browser extension. With no argument it prints the current choice, or nothing: "Omarchy picks no agent for you, so the menu leaves every entry unchecked until one is chosen." The menu entries are the `setup.default.agent.*` items in [`default/omarchy/omarchy-menu.jsonc`](https://github.com/omacom/omarchy/blob/quattro/default/omarchy/omarchy-menu.jsonc). A first-run hook ([`install/user/first-run/setup-agent.hook`](https://github.com/omacom/omarchy/blob/quattro/install/user/first-run/setup-agent.hook)) sends one critical notification, "Set your default agent", whose click action is `omarchy menu summon setup.default.agent`.
- **Launch**: [`bin/omarchy-agent`](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-agent) is the single launcher. It changes into `~/Work` when started from `$HOME` ("agents refuse to remember trust for `$HOME`"), reads the default, and builds a command with that harness's own spelling of "don't stop to ask":

  | Harness | Unattended launch |
  |---|---|
  | claude | `claude --permission-mode auto [-- prompt]` |
  | codex | `codex --approve-for-me` |
  | opencode | `opencode --auto [--prompt]` |
  | agy | `agy --dangerously-skip-permissions` |
  | copilot | `copilot --allow-all` |
  | crush | `crush --yolo` / `crush run <prompt>` |
  | grok | `grok --permission-mode bypassPermissions` |
  | cursor-agent | `cursor-agent --yolo --trust` |
  | hermes | `hermes --yolo` / `hermes chat --yolo --tui --query=` |
  | muse | `muse --approval-mode never` (keeps Muse's sandbox) |
  | omp | `omp --auto-approve` |
  | ori | `ori code [--interactive --prompt]` |
  | openclaw | `omarchy-launch-openclaw --tui` |
  | pi | `pi [prompt]` (no flag exists) |

  Without `--inline` it execs `omarchy-launch-tui --app-id=org.omarchy.agent <command>`, and [`bin/omarchy-launch-tui`](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-launch-tui) is `setsid uwsm-app -- xdg-terminal-exec --app-id=... -e ...`, so the agent opens in the user's default terminal emulator as its own systemd scope, with a fixed window class that window rules and themes can target (today only the generic `org\.omarchy\..*` terminal-tag rule in [`apps/terminals.lua`](https://github.com/omacom/omarchy/blob/quattro/default/hypr/apps/terminals.lua) matches it).
- **Entry points into the launcher**: the keybinding `Super+Shift+Ctrl+A` runs `omarchy-agent --pick` ([`bindings/utilities.lua`](https://github.com/omacom/omarchy/blob/quattro/default/hypr/bindings/utilities.lua) line 97), which opens the picker menu if nothing is chosen yet; the Quake scratchpad's `on_created_empty` runs `omarchy-agent` ([`qconsole.lua`](https://github.com/omacom/omarchy/blob/quattro/default/hypr/qconsole.lua)); a right-click on the bar's agents icon runs `omarchy-agent`; `omarchy agent prompt "..."` goes through [`bin/omarchy-agent-prompt`](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-agent-prompt); and the shell aliases in [`default/bash/aliases`](https://github.com/omacom/omarchy/blob/quattro/default/bash/aliases) are `a` (`omarchy-agent --inline`), `c` (`opencode --auto`), `cx` (`claude --permission-mode auto`), `cy` (`codex --approve-for-me`), `h` (`herdr`), plus `ic`/`ix`/`icx`, which open a tmux three-pane dev layout with the agent in the side pane.

### 2.4 The terminal session layer: herdr beside tmux

Omarchy's terminal-first workflow has a deliberate session-harness layer under the agent. In v4 that is **herdr**, upstream [`herdrdev/herdr`](https://github.com/herdrdev/herdr) (Rust, Apache-2.0, self-described as "the runtime your coding agents live on": a tmux-style multiplexer that marks each pane working/blocked/idle and exposes a CLI and socket API agents can drive). Omarchy builds it from source as a pacman package ([`omarchy-pkgs/pkgbuilds/herdr/PKGBUILD`](https://github.com/omacom/omarchy-pkgs/blob/master/pkgbuilds/herdr/PKGBUILD), maintainer field DHH, `pkgver=0.9.0`) and lists it in the base packages. The shipped config [`config/herdr/config.toml`](https://github.com/omacom/omarchy/blob/quattro/config/herdr/config.toml) states its intent in the first line: "Mirrors the Omarchy tmux config in config/tmux/tmux.conf: tmux session -> herdr workspace, tmux window -> herdr tab, tmux pane -> herdr pane", with the same `ctrl+space` prefix. tmux stays installed with [`config/tmux/tmux.conf`](https://github.com/omacom/omarchy/blob/quattro/config/tmux/tmux.conf). Keybindings: `Super+Ctrl+Return` opens herdr, `Super+Alt+Return` opens tmux, `Super+Ctrl+K` / `Super+Alt+K` show their cheat sheets ([`bin/omarchy-menu-herdr-keybindings`](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-menu-herdr-keybindings) diffs `herdr --default-config` against the user file).

The agent-oriented layout helpers are bash functions: [`default/bash/fns/herdr`](https://github.com/omacom/omarchy/blob/quattro/default/bash/fns/herdr) defines `hdl <agent>` (editor / agent / terminal three-way split), `hds` (four-way with `hunk diff --watch` and opencode), `hdlm` (one `hdl` per subdirectory as tabs), and `hsl <n> <cmd>` (a square grid of n agents); [`default/bash/fns/tmux`](https://github.com/omacom/omarchy/blob/quattro/default/bash/fns/tmux) has the `tdl`/`tds`/`tdlm`/`tsl` equivalents; [`default/bash/fns/worktrees`](https://github.com/omacom/omarchy/blob/quattro/default/bash/fns/worktrees) adds `ga`/`gd` to create and remove git worktrees for parallel agents. SSH keepalive and terminal-state cleanup for remote multiplexers were added in v4.0.0 for the same reason ([`install/config/ssh-keepalive.sh`](https://github.com/omacom/omarchy/blob/quattro/install/config/ssh-keepalive.sh), [`default/bash/fns/ssh-reconnect`](https://github.com/omacom/omarchy/blob/quattro/default/bash/fns/ssh-reconnect)).

### 2.5 The shipped skills

**Source and fan-out.** Both skills live in the package at `$OMARCHY_PATH/default/agents/skills/` ([`default/agents/skills/`](https://github.com/omacom/omarchy/tree/quattro/default/agents/skills)). [`bin/omarchy-provision-user`](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-provision-user) (lines 87 to 101) symlinks every skill directory into six harness locations: `~/.agents/skills` (the vendor-neutral convention), `~/.claude/skills`, `~/.codex/skills`, `~/.pi/agent/skills`, `~/.gemini/config/skills`, `~/.hermes/skills`, plus each `~/.hermes/profiles/*/skills`. Later additions were back-filled by migrations ([`migrations/1786539345.sh`](https://github.com/omacom/omarchy/blob/quattro/migrations/1786539345.sh) adds `diagnose-crash`, [`1786719479.sh`](https://github.com/omacom/omarchy/blob/quattro/migrations/1786719479.sh) adds the Gemini path, [`1787843905.sh`](https://github.com/omacom/omarchy/blob/quattro/migrations/1787843905.sh) adds Hermes). Harnesses without a skill mechanism are handled by prompt: the crash launcher tells the agent "If your harness has no skill mechanism, read the skill files directly."

**`omarchy` skill** ([`SKILL.md`](https://github.com/omacom/omarchy/blob/quattro/default/agents/skills/omarchy/SKILL.md), about 290 lines, plus six topic guides). Frontmatter description: "REQUIRED for end-user customization of Linux desktop, window manager, or system config. Use when editing ~/.config/hypr/, ~/.config/omarchy/, ~/.config/alacritty/, ~/.config/foot/, ~/.config/kitty/, or ~/.config/ghostty/." Its rules: never modify `/usr/share/omarchy/` (package-owned, overwritten on update), write only under `~/.config/`, prefer stock `omarchy` commands over hand edits, use `sudo` when a terminal is present and `pkexec` when it is not, and always seek confirmation before `omarchy refresh <app>` (which resets a config with a backup). It provides a decision framework (stock command? config edit? theme? hook? package? plugin clone? unsure? then `omarchy commands`).

  - (a) **Customizing Hyprland**: [`hyprland.md`](https://github.com/omacom/omarchy/blob/quattro/default/agents/skills/omarchy/hyprland.md) teaches the `~/.config/hypr/*.lua` layout, that Hyprland auto-reloads on save but must be validated with `hyprctl reload` and `hyprctl configerrors`, the `o.bind` / `o.rebind` / `hl.unbind` semantics (and to tell the user what a rebound key replaced), monitor configuration in `monitors.lua`, and a "CRITICAL" instruction to fetch the live Hyprland wiki before writing any window rule because the syntax has changed several times.
  - (b) **Managing plugins and the shell**: [`plugins.md`](https://github.com/omacom/omarchy/blob/quattro/default/agents/skills/omarchy/plugins.md) covers `~/.config/omarchy/shell.json` (hot-reloaded), `omarchy bar move/put/set`, `idle.screensaver`/`idle.lock`, and the rule "To customize a built-in bar widget, never edit `$OMARCHY_PATH/shell/plugins/`. Clone it into the user plugin directory instead: `omarchy plugin clone omarchy.workspaces`", which relies on the clone-and-reroute behaviour of [`bin/omarchy-plugin-clone`](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-plugin-clone).
  - [`theming.md`](https://github.com/omacom/omarchy/blob/quattro/default/agents/skills/omarchy/theming.md) (theme commands, building a theme, which files an installed theme may not ship, overlay-vs-fork), [`hooks.md`](https://github.com/omacom/omarchy/blob/quattro/default/agents/skills/omarchy/hooks.md), [`capture.md`](https://github.com/omacom/omarchy/blob/quattro/default/agents/skills/omarchy/capture.md) (screenshot/recording/OCR/share commands), and [`contributing.md`](https://github.com/omacom/omarchy/blob/quattro/default/agents/skills/omarchy/contributing.md) (verified bugs to GitHub issues, `omarchy debug --no-sudo --print`, never develop against `/usr/share/omarchy`, follow the repo's `AGENTS.md`, run `./test/all`).

**`diagnose-crash` skill** ([`SKILL.md`](https://github.com/omacom/omarchy/blob/quattro/default/agents/skills/diagnose-crash/SKILL.md), [`reporting.md`](https://github.com/omacom/omarchy/blob/quattro/default/agents/skills/diagnose-crash/reporting.md)). This is (c), **diagnosing issues**. It walks the agent through `coredumpctl info`, ruling out OOM, correlating the crash with journal entries and recent package updates, reading all thread stacks, symbolizing through Arch's debuginfod with a temporary core file that is deleted afterwards, and reporting cause, mechanism, data loss and recurrence risk with proof separated from inference. It draws a hard line: "Diagnosis reads; it does not fix, tidy, or reconfigure", and the only change it may make is offering `omarchy crash mute <program>`. `reporting.md` limits Omarchy's blame surface to its own scripts, shell, config, themes and installers, requires a search of open and closed issues, requires explicit user sign-off on title and body before `gh issue create`, and ends every report with "Filed by <model name> via <agent harness>".

**Pipeline behind (c).** [`bin/omarchy-crash-watch`](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-crash-watch) (user unit `omarchy-crash-watch.service`) follows `journalctl -f -o json MESSAGE_ID=fc2e22bc6ee647b6b90729ab34a250b1` (systemd-coredump's message id), dedupes, honours mutes, and, only when a default agent is set, sends a critical notification "Process crashed: <comm>", "Click to diagnose with AI", whose action is [`bin/omarchy-agent-crash <pid>`](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-agent-crash). That script builds a prompt with the crash facts and the literal path of the skill and execs `omarchy-agent --prompt`, so the diagnosis runs in the same unattended launch path as any other agent session. Toggle: [`bin/omarchy-toggle-crash-capture`](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-toggle-crash-capture); per-program mute: [`bin/omarchy-crash-mute`](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-crash-mute). General diagnostics for the agent to run: [`bin/omarchy-debug`](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-debug) (`inxi`, `dmesg`, journal errors, `pacman -Q` inventory).

**Developer-side skills are a separate tree.** [`AGENTS.md`](https://github.com/omacom/omarchy/blob/quattro/AGENTS.md) (with [`CLAUDE.md`](https://github.com/omacom/omarchy/blob/quattro/CLAUDE.md) as a one-line `@AGENTS.md` pointer) governs agents working on the Omarchy codebase and fans out to seven contributor guides in [`agents/skills/`](https://github.com/omacom/omarchy/tree/quattro/agents/skills) (command metadata, install scripts, shell development, icon font, acceptance tests, visual verification, migrations). These are not installed on user machines; only `default/agents/skills/` is.

### 2.6 Theme sync, usage telemetry, and plugins

- **Theme sync into harnesses.** `omarchy-theme-set` calls [`bin/omarchy-theme-set-claude`](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-theme-set-claude) (writes `~/.claude/themes/omarchy.json`, optionally sets `"theme": "custom:omarchy"` in `~/.claude/settings.json`), [`omarchy-theme-set-pi`](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-theme-set-pi) (`~/.pi/agent/themes/omarchy-system.json`, activated at install), [`omarchy-theme-set-hermes`](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-theme-set-hermes) (a validated skin YAML in `~/.hermes/skins/`), [`omarchy-theme-set-t3code`](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-theme-set-t3code), and `omarchy-restart-opencode` (SIGUSR2 so OpenCode reloads its `"theme": "system"` from [`config/opencode/opencode.json`](https://github.com/omacom/omarchy/blob/quattro/config/opencode/opencode.json)).
- **Usage panel.** The `omarchy.agents` bar plugin ([`shell/plugins/agents/README.md`](https://github.com/omacom/omarchy/blob/quattro/shell/plugins/agents/README.md)) displays JSON records that [`bin/omarchy-agent-usage-update`](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-agent-usage-update) regenerates every 15 minutes by running every `omarchy-agent-usage-<provider>` collector in parallel. Collectors ship for Claude ([`omarchy-agent-usage-claude`](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-agent-usage-claude), Python, reads Anthropic's OAuth usage endpoint and `~/.claude/projects` transcripts), Codex, and Fireworks. The icon appears only once usage has been observed; right-click launches the default agent.
- **Plugin system as the extension substrate.** The agents panel is an ordinary shell plugin, and the first-party-adjacent [`basecamp/omarchy-hey-plugin`](https://github.com/basecamp/omarchy-hey-plugin) and [`basecamp/omarchy-basecamp-plugin`](https://github.com/basecamp/omarchy-basecamp-plugin) use the same `manifest.json` shape (`kinds: ["service","bar-widget"]`), installed with `omarchy plugin add <git-url> --enable`.

### 2.7 Characterization

Read as a whole, the agent layer is an opinionated selection of the entire substrate rather than a folder of prompts:

1. **Distribution**: mise as the universal tool manager for agent CLIs, with lazy stubs and one update path (`omarchy update` / `mup`).
2. **Invocation**: one launcher, one window class, one cwd rule, one unattended-mode table, wired to a keybinding, a scratchpad, a bar click, a notification action, and shell aliases.
3. **Session harness**: herdr chosen and packaged as the agent-aware multiplexer, configured to mirror tmux so the two are interchangeable, with layout functions for agent swarms and worktree helpers for isolation.
4. **Knowledge**: two skills authored against Omarchy's own command surface, fanned out to every harness's skill directory from one package-owned source, with explicit safety boundaries (`/usr/share/omarchy` read-only, plan mode recommended, `omarchy reinstall configs` as the rollback).
5. **Feedback loops**: crash events flow to the agent; theme changes flow to the agent; usage flows back to the bar.

What is *not* there: no shipped default choice, no Omarchy-owned model or runtime, no MCP servers or hooks configuration for any harness, and no per-harness config beyond the theme files and OpenCode's two-line settings file.

## 3. Portability to Fedora

Method: every package name in Omarchy's lists was checked against a Fedora 44 host (`dnf5 5.4.3.0`, SELinux `Enforcing`, only `fedora` and `updates` enabled, which matches a stock Workstation) and against the COPR API for [`solopasha/hyprland`](https://copr.fedorainfracloud.org/coprs/solopasha/hyprland/) (the long-standing general Fedora Hyprland COPR) and [`agaspar/omedora-4`](https://copr.fedorainfracloud.org/coprs/agaspar/omedora-4/) (the COPR behind the community Omarchy-on-Fedora port, section 3.5). Queries were run on 2026-09-16; versions move.

### 3.1 Model differences that matter

| Dimension | Arch / Omarchy | Fedora 44 | Consequence |
|---|---|---|---|
| Release model | Rolling; Omarchy adds a one-month-delayed Arch mirror plus its own `[omarchy]` repo with `stable`/`rc`/`edge` channels | Point release plus `updates`; fast-moving desktop software lives in COPRs maintained by individuals | The Hyprland ecosystem's currency on Fedora depends on which COPR you pick (section 3.3). Everything else Omarchy needs is in Fedora main at current versions. |
| Package tooling | pacman, `yay` for AUR, libalpm hooks; Omarchy wraps them in `omarchy-pkg-*`, `omarchy-update-*`, and the update guard | dnf5, RPM, COPR, Flatpak; no equivalent of ALPM hooks | Every `omarchy-pkg-*` wrapper and the three libalpm hooks need dnf/rpm replacements or removal. `omarchy update` does not survive a straight port. |
| Security model | No MAC by default; `ufw` firewall | SELinux enforcing; `firewalld` | PAM stacks are `authselect`-generated. Omarchy's `sed` edits to `/etc/pam.d/sddm` and `system-auth` ([`install/login/sddm.sh`](https://github.com/omacom/omarchy/blob/quattro/install/login/sddm.sh), [`install/config/increase-lockout-limit.sh`](https://github.com/omacom/omarchy/blob/quattro/install/config/increase-lockout-limit.sh)) must be rewritten, and [`install/config/firewall.sh`](https://github.com/omacom/omarchy/blob/quattro/install/config/firewall.sh) must be replaced with firewalld rules or firewalld disabled first. |
| Boot and snapshots | Limine, `limine-snapper-sync`, btrfs + snapper, `mkinitcpio`, custom `linux-omarchy` kernel (v4.0.4) | GRUB2 or systemd-boot, dracut, stock kernel, btrfs default with snapper available | Limine is not packaged for Fedora at all. Drop the bootloader/snapshot integration and the kernel; keep snapper if wanted. |
| Containers | `docker` package | podman default; `moby-engine` or Docker's own repo for Docker | Docker TUI, `ufw-docker`, and the Windows VM flow assume Docker. |
| GPU | `nvidia-dkms`, `nvidia-open-dkms`, `nvidia-580xx-*` | RPM Fusion `akmod-nvidia` | Replace [`install/hardware/nvidia.sh`](https://github.com/omacom/omarchy/blob/quattro/install/hardware/nvidia.sh); [`default/hypr/nvidia.lua`](https://github.com/omacom/omarchy/blob/quattro/default/hypr/nvidia.lua) itself is portable. |
| Install root | `/usr/share/omarchy` from the `omarchy` package; `/etc/skel` seeding from `omarchy-settings` | No package | Either build RPMs (Omedora does) or clone the tree and export `OMARCHY_PATH`, which the Lua bootstrap and every script honour. |

**SELinux and policy attention points for this layer**

1. **Login keyring and PAM.** Omarchy strips `pam_gnome_keyring.so` from SDDM's PAM stack and edits `system-auth` for faillock. On Fedora those files are authselect-managed; edit via `authselect` profiles or custom `/etc/pam.d/omarchy-lock-*` files that `include system-auth`. Fedora's own policy has an open issue with `pam_gnome_keyring` at login under SELinux ([fedora-selinux/selinux-policy#2364](https://github.com/fedora-selinux/selinux-policy/issues/2364)), and Omarchy has an issue about its own stripping being incomplete ([omacom/omarchy#10243](https://github.com/omacom/omarchy/issues/10243)).
2. **Lock screen.** The v4 lock is Quickshell's `WlSessionLock` authenticating through `/etc/pam.d/omarchy-lock-password`, written by [`bin/omarchy-apply-lock`](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-apply-lock). Write a Fedora-shaped version of that file rather than running the script verbatim. For a v3-style port, check that the COPR `hyprlock` RPM ships `/etc/pam.d/hyprlock`.
3. **Files under `/usr/share/omarchy`.** If the tree is copied there by hand, run `restorecon -R /usr/share/omarchy` so scripts get `usr_t`/`bin_t` labels; a git checkout under `$HOME` with `OMARCHY_PATH` exported avoids the question entirely.
4. **Plymouth.** Theme files go to `/usr/share/plymouth/themes/omarchy/`; on Fedora regenerate with `plymouth-set-default-theme -R` (dracut), not mkinitcpio. `restorecon` after copying.
5. **firewalld vs ufw**, **podman vs docker**, **akmod vs dkms**: policy decisions, not SELinux bugs, but each Omarchy script that assumes the Arch side must be swapped or skipped.
6. **uwsm and user units.** No Fedora-specific denials were found for uwsm, `systemd --user` units, or `xdg-desktop-portal-hyprland` in this research; treat as "watch `ausearch -m AVC -ts recent` after first login", not a known blocker.
7. **systemd-coredump** is present on Fedora 44 (`/usr/lib/systemd/systemd-coredump` from `systemd-udev 259.8`), so the crash pipeline's journal filter works unchanged.

- `omarchy-install-ai-*` (ChatGPT, Claude desktop, Hermes Desktop, OpenClaw, T3 Code, Perplexity) call `omarchy-pkg-add` on Arch/AUR packages; the OpenClaw CLI is the `openclaw` pacman package; `omarchy-install-hermes-cli` gates on `omarchy-pkg-present hermes-desktop`. ### 3.5 Existing community ports (secondary sources, not endorsed by Omarchy)

The official "Omarchy on..." manual page ([`manual/49-omarchy-on.md`](https://github.com/omacom/omarchy/blob/quattro/manual/49-omarchy-on.md)) lists Apple Silicon, VMs, Steam Deck and NixOS, and does not mention Fedora. Community efforts:

- **Omedora** ([AndrewGaspar/omedora](https://github.com/AndrewGaspar/omedora), branch `omedora-4`, COPR `agaspar/omedora-4`, 4 stars, last push 2026-09-12). The most faithful port. It is "a desktop you add to Fedora", not a distro: GDM or SDDM, GRUB, dracut and Plymouth stay as Fedora installed them, and "Omedora" appears as a login session. It mirrors Quattro's packaging model, so `omedora` and `omedora-settings` RPMs own `/usr/share/omarchy` and the `omarchy-*` commands, and the bootstrap shows a plan and asks before installing. Everything Fedora and RPM Fusion lack comes from its own COPR (Hyprland 0.56.2 and libraries, Quickshell 0.3, uwsm, herdr, mise, starship, lazygit, lazydocker, Nerd fonts, voxtype, tensaku, ttfx, omacalc, omacut, omawrite). Fedora 44 Workstation x86_64 only. Labelled beta with "rough edges"; the author points at the `omedora-3` branch (the v3.8.4 line) for a stable release. Its `hyprland-omedora` metapackage build was failing at query time.
- **Omadora** ([elpritchos/omadora](https://github.com/elpritchos/omadora), 123 stars, last push 2026-08-17). The most popular Fedora effort, but deliberately a minimal Hyprland install "based on the Omarchy implementation and patterns", built from official Fedora repos with Hyprland, mise and starship as the only COPR exceptions. Installs from an Everything netinstall into `~/.local/share/omadora`, has no seamless login (you run `omadora` after logging in), and predates the Quattro shell. It omits most Omarchy apps on purpose.
- **omarchy-fedora** ([djdanielsson/omarchy-fedora](https://github.com/djdanielsson/omarchy-fedora), 0 stars, last push 2026-09-15). A Fedora 44 `bootc` image-mode desktop: a Containerfile on `fedora-bootc:44` layering Hyprland 0.56.2, Quickshell, SDDM and uwsm "ported from Omarchy", with Flatpak apps, Podman and Distrobox, and weekly image rebuilds. Installed from an ISO or `bootc switch`; updates are atomic and rollbackable, which is a Fedora-native answer to the snapshot-and-rollback role Limine and snapper play in Omarchy. One-person project; useful as a design reference.
- **Fedarchy** ([c3d/fedarchy](https://github.com/c3d/fedarchy), 0 stars, last push 2025-10-15). Stale. Targets Fedora 42, claims "100% feature parity", and uses Distrobox to pull Walker from the AUR, but the actual setup is WezTerm, Fish, a Dracula waybar and Emacs bindings, so it is a personal Hyprland config inspired by Omarchy rather than a port of its files. The install URL in its README is still a placeholder.

For comparison, the NixOS ports split the same way: [zicochaos/omarchy-nix](https://github.com/zicochaos/omarchy-nix) (33 stars, pushed 2026-09-14) vendors the upstream `quattro` tree, packages the 13 upstream-only packages, and ships VM tests, while [henrysipp/omarchy-nix](https://github.com/henrysipp/omarchy-nix) (799 stars, the one the manual links) is an unmaintained v1-era reimplementation whose author has moved back to Arch Omarchy. Two patterns have held up: vendor the real tree and patch the Arch seams, or re-create a small subset natively. Reimplementations that stray from the shipped files go stale within months because upstream moves weekly.

## 4. Fedora replication verdict

### 4.1 Per-layer verdict

| Layer | Verdict | Why |
|---|---|---|
| Hyprland compositor with Omarchy's Lua config | **Friction, doable** | Needs Hyprland >= 0.55 from the `omedora-4` COPR or a source build; `solopasha/hyprland` is too old. Once installed, `default/hypr/*.lua` runs unchanged with `OMARCHY_PATH` set. |
| Quickshell `omarchy-shell` (bar, menu, launcher, notifications, OSD, lock, idle, wallpaper, polkit) | **Friction, doable** | Needs quickshell 0.3.x (COPR), the Nerd font, and the Fedora-shaped lock PAM file. The QML and scripts themselves are portable. The menu's package guards need a `pacman -Q` to `rpm -qa` shim. |
| Capture, clipboard, OCR, portals, terminals, file manager | **Clean win** | Every package is in Fedora main except the portal backend and share picker (COPR). |
| Login and session (SDDM, uwsm, plymouth) | **Friction** | uwsm from COPR; PAM/authselect and keyring behaviour must be redone; plymouth theme regeneration via dracut. GDM must be disabled. |
| Theming | **Clean win** | Bash plus templates plus `hyprctl reload` plus shell IPC. Only the plymouth, Chromium policy, and VS Code paths need checking. |
| Boot, snapshots, kernel, firewall, docker, update guard, migrations | **Not worth it** | Limine and `linux-omarchy` have no Fedora path; snapper boot integration would need `grub-btrfs`; firewalld and podman are Fedora's answers; `omarchy update` and the 121 migrations are pacman-shaped. Use dnf, keep a git checkout of the tree, and cherry-pick config migrations by hand. |
| Agent harness (mise stubs, `omarchy-agent`, default picker, herdr, aliases) | **Clean win** | Pure bash and mise; herdr is a single binary with existing COPRs. |
| Skills and crash diagnosis | **Clean win with two edits** | Symlink fan-out and skill text are distro-neutral; change the package idiom and the debuginfod URL. systemd-coredump is present on Fedora. |
| Desktop AI apps and OpenClaw | **Friction** | Installed as Arch/AUR packages; substitute Flatpak or upstream installers. |

### 4.2 Recommended shape

If the desktop is ported at all (section 4.6 argues against it), two shapes are viable; the second is the safer of the two.

- **Path A, quattro-faithful**: enable `agaspar/omedora-4`, install the Omarchy tree at v4.0.4, and run the Quickshell shell. This reproduces the current Omarchy experience and the agent layer exactly, at the cost of depending on a beta community COPR for the compositor and shell.
- **Path B, layered**: take the agent-harness layer and the Omarchy scripts/theme system wholesale (they are portable), but run the compositor stack from whichever COPR is current for your Fedora release, and be willing to fall back to the v3.8.4 classic component set (waybar, mako, hyprlock, hypridle, swaybg from Fedora main and `solopasha/hyprland`) if the Lua-era COPR lags. This keeps the "agentic" substrate while decoupling from the fastest-moving dependency.

### 4.4 Assembly steps for the Hyprland layer (Path A)

These steps follow the build-time map in [`docs/file-layout.md`](https://github.com/omacom/omarchy/blob/quattro/docs/file-layout.md) and the `omarchy-settings` PKGBUILD, replacing the package with a checkout. They were derived from the sources, not executed in this research.

1. **Base**: Fedora 44 Workstation, btrfs, SELinux enforcing, GRUB/dracut/firewalld left as installed. `sudo dnf install` the lists in 4.3. If NVIDIA: RPM Fusion `akmod-nvidia`.
2. **Omarchy tree**: `git clone --branch v4.0.4 https://github.com/omacom/omarchy.git ~/.local/share/omarchy`, then `export OMARCHY_PATH=$HOME/.local/share/omarchy` in a profile snippet. Every Lua module, script, and the shell read this variable ([`default/hypr/paths.lua`](https://github.com/omacom/omarchy/blob/quattro/default/hypr/paths.lua), [`bin/omarchy-launch-shell`](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-launch-shell)). Alternatively copy to `/usr/share/omarchy` and `restorecon -R` it. Put `$OMARCHY_PATH/bin` on `PATH`.
3. **Session files (root)**: copy [`default/wayland-sessions/omarchy.desktop`](https://github.com/omacom/omarchy/blob/quattro/default/wayland-sessions/omarchy.desktop) to `/usr/share/wayland-sessions/`; copy [`default/uwsm/env.d/10-omarchy`](https://github.com/omacom/omarchy/blob/quattro/default/uwsm/env.d/10-omarchy) to `/usr/share/uwsm/env.d/` and set `OMARCHY_PATH` in it; copy the `/etc/sddm.conf.d/10-*.conf` drop-ins the `omarchy-settings` package ships (from [`default/sddm/`](https://github.com/omacom/omarchy/tree/quattro/default/sddm) and the `etc/` tree); `systemctl disable gdm && systemctl enable sddm`.
4. **User config**: copy `$OMARCHY_PATH/config/` into `~/.config/` (this is what `/etc/skel` would seed: `hypr/*.lua`, `omarchy/shell.json`, terminal configs, `herdr/config.toml`, `tmux/tmux.conf`, `starship.toml`, `opencode/opencode.json`); install [`default/bashrc`](https://github.com/omacom/omarchy/blob/quattro/default/bashrc) or source [`default/bash/rc`](https://github.com/omacom/omarchy/blob/quattro/default/bash/rc) from your own `.bashrc`; copy [`default/systemd/user/*.service`](https://github.com/omacom/omarchy/tree/quattro/default/systemd/user) to `~/.config/systemd/user/` and enable the ones listed in [`enable-user-units.sh`](https://github.com/omacom/omarchy/blob/quattro/install/user/first-run/enable-user-units.sh); copy `default/fontconfig/conf.avail/50-omarchy.conf` and the `default/fonts/omarchy/omarchy.ttf` icon font into `~/.local/share/fonts/`; `fc-cache`.
5. **PAM**: create `/etc/pam.d/omarchy-lock-password` with Fedora's include style (`auth include system-auth`, `account include system-auth`) rather than running [`bin/omarchy-apply-lock`](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-apply-lock) verbatim; add the fingerprint variant only if `fprintd-list` shows enrollments. Do not run [`install/login/sddm.sh`](https://github.com/omacom/omarchy/blob/quattro/install/login/sddm.sh) or [`increase-lockout-limit.sh`](https://github.com/omacom/omarchy/blob/quattro/install/config/increase-lockout-limit.sh); use `authselect` if you want the same effect.
6. **Package shim**: provide dnf-backed replacements for `omarchy-pkg-present` (`rpm -q`), `omarchy-pkg-add` (`dnf install`), `omarchy-cmd-present` (already `command -v`), and stub `omarchy-update-pacman*`, `omarchy-update-aur-pkgs`, `omarchy-update-orphan-pkgs`. Omedora's patch stack is the reference for this. Skip [`install/config/all.sh`](https://github.com/omacom/omarchy/blob/quattro/install/config/all.sh) apart from `theme-system.sh`, `docker.sh` (only if using moby-engine), `ssh-keepalive.sh`, and `lockscreen-pam.sh` (adapted).
7. **Theme**: run `omarchy-theme-set tokyo-night` (or run [`install/user/theme.sh`](https://github.com/omacom/omarchy/blob/quattro/install/user/theme.sh)) to populate `~/.local/state/omarchy/current/theme/`; skip `omarchy-plymouth-set` or follow it with `plymouth-set-default-theme -R omarchy`.
8. **First login**: choose "Omarchy (Hyprland uwsm)" in SDDM. Check `hyprctl configerrors`, `omarchy-shell shell ping`, `journalctl --user -t omarchy-shell`, and `ausearch -m AVC -ts recent`. Expected first-round issues are the lock PAM file and keyring unlock.
9. **Agent layer**: `mise` from the COPR; run `install/user/mise.sh` (creates the 13 stubs); run the skill loop from `bin/omarchy-provision-user` (or `omarchy-provision-user` itself if the package shims are in place); `omarchy default agent <name>`; `systemctl --user enable --now omarchy-crash-watch.service`. Edit the two skill references noted in 3.4.
10. **Updates**: `dnf upgrade` for packages, `git -C $OMARCHY_PATH pull` for the tree, then read new `migrations/*.sh` and apply the config-only ones by hand. Do not run `omarchy update`.

### 4.5 What to expect

- **Clean**: keybindings, window rules, themes, menu, notifications, clipboard, screenshots, capture, herdr/tmux, the agent launcher, skills, crash diagnosis, usage panel.
- **Friction**: lock/keyring PAM, first-login SELinux denials, plymouth branding, screen-share portal from COPR, font glyphs until the Nerd font is installed, every menu entry that installs software (they call pacman).
- **Not reproduced**: Limine boot menu with snapshot rollback, `linux-omarchy`, ufw rules, `omarchy update` and channels, ISO/unattended install, factory reset, Windows VM via Docker, AUR-only apps (1Password beta, Spotify, Typora via pacman).

### 4.6 Recommendation

**Do not port the Omarchy desktop to Fedora. Either migrate to Omarchy, or stay on Fedora and take only the agent layer.** Which of the two depends on what the desktop is for.

Why the middle path is the worst option:

- The value of Omarchy 4 is the integrated, maintained whole: one shell process, one update pipeline with channels and snapshots, weekly releases, and a funded team plus a large community fixing the seams. A Fedora port delivers the files but not the maintenance. Omedora is one person and beta; every upstream release widens the gap, and the porter becomes the maintainer of every seam listed in section 3.2.
- The Hyprland stack is the fastest-moving dependency in the picture, and on Fedora it lives in one-person COPRs. That is the opposite of the reason to choose Fedora.
- The pieces that are genuinely Fedora-incompatible (Limine snapshots, the custom kernel, the update guard, the migrations) are the operational safety net that makes rolling Arch tolerable. A port gets Omarchy's churn without Omarchy's rollback. The bootc approach in section 3.5 is the only Fedora-native answer to that, and it is a one-person experiment.

**Migrate to Omarchy if** the goal is the desktop itself: the tiling workflow, the shell, the themes, and agent integration that evolves with the product. Its costs are real but bounded. Arch rolling is softened by the one-month-delayed mirror and pre-update snapshots; the custom kernel and Limine are opinionated but supported; there is no SELinux. Do it on real hardware, and use the dual-boot installer ([`manual/50-dual-boot-install.md`](https://github.com/omacom/omarchy/blob/quattro/manual/50-dual-boot-install.md)) to live in it for two weeks before committing a daily driver.

**Stay on Fedora if** the goal is the agentic workflow rather than the desktop, or if SELinux, organisational policy, or a stable point-release base matter. The agent substrate is the portable 90 percent and is an afternoon of work: mise plus the stub script, `omarchy-agent` and the default picker, herdr with the tmux-mirrored config, the two skills symlinked into the harness directories, and the coredump watcher. It works under GNOME or KDE and does not need Hyprland. If tiling is wanted later, run Hyprland from a COPR with a personal config rather than Omarchy's.

**Suggested sequence.** Set up the agent layer on Fedora first; it is low risk and reversible either way. Then settle the desktop question by experience, not by reading: dual-boot Omarchy on a laptop for a couple of weeks. If the Omarchy machine becomes the one you reach for, migrate and stop maintaining a Fedora desktop. If it does not, nothing has been lost and the workflow stays.
