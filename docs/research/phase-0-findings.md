## Corrections to this guide
1. **Host is `qemu:///session`, not `qemu:///system`.** Running `virt-install` as an unprivileged user (no `--connect`) creates the VM under the per-user session daemon. Every `virsh` / `virt-clone` / `virt-viewer` must target it — `export LIBVIRT_DEFAULT_URI=qemu:///session` or pass `--connect qemu:///session`. Session disks live in `~/.local/share/libvirt/images/`. No `sudo` needed for VM ops; user-mode NAT gives the guest outbound network.
2. **`virt-viewer` needs `--attach`.** With `--graphics spice,gl.enable=yes,...,listen=none`, SPICE uses a local-only socket, so `virt-viewer --connect qemu:///session --attach tinkero-spike` is required. A plain connect fails with "Display can only be attached through libvirt with --attach".
3. **Optimus host: pin virgl to the Intel render node.** Added `rendernode=/dev/dri/by-path/pci-0000:00:02.0-render` to the `--graphics` line so virgl renders on the Intel iGPU, not the proprietary NVIDIA driver. The guide's line-23 NVIDIA warning does not apply to a hybrid host as long as virgl is steered at Intel. Boot menu + installer rendered fine this way.
4. **Anaconda F44 WebUI can look frozen at "Generating initramfs" when the install is actually complete.** The legacy `/tmp/anaconda.log` only logs backend startup; the WebUI logs to the journal. Sat idle (0% CPU, no dracut/rpm process, no journal progress ~15 min) while the disk was in fact fully written (3.5 GB root, populated `/boot` + EFI). Force-off + boot from disk landed in gnome-initial-setup — install had succeeded. If it looks frozen: check `df` on `/mnt/sysroot`; if populated, boot the disk rather than reinstalling.
5. **`authselect local` on F44 enables `with-fingerprint` by default** (also `with-silent-lastlog`, `with-mdns4`). Not mentioned in the guide. No fingerprint reader in the VM, so `pam_fprintd` should fall through to password — but `password-auth` carries an extra `auth` module, so it is the first suspect if section 6 `pamtester` behaves oddly.
6. **F44's default GNOME appearance is Light** (`color-scheme 'default'`), so the guide's "set Appearance to Light" (line 64) is *not* a non-default canary here. Set **Dark** (`prefer-dark`) instead for a meaningful Q5 restore check.
7. **Heredoc paste caveat:** pasting the section-3 `snap.sh` heredoc with leading indentation breaks it (the closing `EOF` must be flush-left). Creating the file with `nano` works. Not a guide bug, but worth a note for anyone executing by paste. Practical workaround used throughout section 5: rewrite `tee <<'EOF'` blocks as `printf ... | sudo tee` one-liners or line-by-line `echo ... | tee -a`, keep every command under ~90 chars (long lines also get a newline injected on paste), and enable/verify units one per line. Multi-line `for` loops are safe (`done` tolerates indent, unlike heredoc `EOF`).
9. **Section 8 autostart wiring uses `o.launch_on_start`, not `hl.on`.** The user `~/.config/hypr/autostart.lua` uses the `o.` API (its own comment: `o.launch_on_start("my-service")`), so the guide's `hl.on("hyprland.start", ...)` form (from upstream's *default* autostart.lua) is wrong for the user file. Used `o.launch_on_start("systemctl --user start tinkero-gnome-restore.service")` — exactly the case guide line 343 anticipated.
8. **Defensive additions in 5.3/5.4 (not in guide):** added an explicit `chmod +x` + `restorecon` on the seven stand-ins, since `tee`/`cp` can create `omarchy-provision-user` without the execute bit. Harmless where files pre-existed (they inherit `+x`/`bin_t` from the 5.2 `mv`).

## Corrections to the spec and audit
- **Positive:** the COPR `agaspar/omedora-4` builds for **Fedora 44** (`baseurl` uses `fedora-$releasever`, resolves to `fedora-44-x86_64`). All 12 requested COPR-stack packages resolved with no `No match` errors, and `hyprland`/`quickshell`/`uwsm` came from the COPR, beating Fedora's older `quickshell` (guide 98–99 concern cleared).
- **Weak-dep bloat (spec 6 candidate):** the COPR-stack `dnf install` pulled `nwg-panel`, `wofi`, `playerctl`, `newt` as *recommends* — a second bar and launcher not part of the intended stack. The `tinkero` RPM install likely wants `--setopt=install_weak_deps=False`. Confirm which package recommends them.
- **`power-profiles-daemon` conflicts with F44's preinstalled `tuned-ppd` (spec 6 correction).** Both provide `ppd-service`. F44 Workstation ships `tuned-ppd` (TuneD implementing the power-profiles-daemon D-Bus API) by default. The spec must **drop `power-profiles-daemon`** and rely on `tuned-ppd` rather than force `--allowerasing` (which would erase a Fedora default, against spec 5). Installed the rest of the Fedora deps without it. **To verify in section 7:** the desktop power widget works against `tuned-ppd`'s D-Bus interface.
- **`fcitx5` missing from the dependency manifest (spec 6 correction).** `omarchy-fcitx5.service` (`ExecStart=/usr/bin/fcitx5 --disable notificationitem`) is enabled, but `fcitx5` is in neither section-4 install list, so the binary is absent → `status=203/EXEC`. Add `fcitx5` to the manifest, or gate the unit on its presence.
- **`omarchy-fcitx5.service` crash-loops with no rate limit.** With the binary missing it restarted **188 times** in a couple of minutes, each cycle firing an `omarchy-crash-watch` "unit recovered" notification (notification storm). Unit needs `StartLimitIntervalSec`/`StartLimitBurst` (and arguably `ConditionPathExists=/usr/bin/fcitx5`).
- **User units leak into the GNOME session (spec correction, high priority).** The five units are `WantedBy=graphical-session.target`, which **GNOME also activates** — so `omarchy-fcitx5` (and the others) start under a plain GNOME login, not just the Tinkero/uwsm session. This is the same hazard the guide flags for `tinkero-gnome-restore` (spike §8, guide lines 313–316). The units should be scoped to the uwsm/Hyprland session, not generic `graphical-session.target`. **First observed:** logging into GNOME triggered a nonstop `omarchy-fcitx5` crash-watch notification loop.
- **GNOME-key leaks from the Tinkero session (audit 6 / spec 4.9).** The Hyprland session modifies `org.gnome.desktop.interface` keys: `text-scaling-factor` via `omarchy-display-text-size` (and a Dell-XPS13 `xps13-text-scaling.sh` from `install/user/all.sh`), and `cursor-theme` (→ `default`, likely the shell's `Panel.qml`). The save/restore prototype's original 3-key list missed both; even after widening, `cursor-theme` leaks due to the save-timing race (see Q5).
- **`pkill -9`/crash → Hyprland Safe Mode.** After an abrupt session kill, the next Tinkero login came up in Hyprland **Safe Mode** (autogenerated config, user config not loaded; `Super+M` to exit). Expected upstream crash-recovery behaviour, but the recovery-path design (spec 4.9) should account for a user landing there after a crash.
- **`org.freedesktop.IBus.session.GNOME.service` fails/recovers under GNOME**, flagged repeatedly by `FUMonitor` (= `omarchy-crash-watch`) — another symptom of the `graphical-session.target` unit leak (crash-watch runs under GNOME and monitors GNOME's own IBus service). Fcitx also warns it needs the GNOME input-method-panel extension. Compounds the earlier unit-leak finding.
- _Dead menu entries (audit 7): not catalogued this run (B2 menu opened; entries not individually audited)._

## Decisions
- **Lock mechanism:** **Quickshell lock + two PAM variants** — confirmed working under SELinux enforcing (Q2/Q3 pass). No need to fall back to `hyprlock`.
- **GNOME restore:** **unit-based restore** (`ExecStop` of a `PartOf=graphical-session.target` oneshot). It fired reliably on all three session ends — menu logout, `loginctl terminate-session`, and `pkill -9 Hyprland` (systemd tears down the target regardless). The autostart `.desktop` fallback never fired → **keep it only as cheap insurance, or drop it.** **Two required fixes before this ships:** (1) widen the key set beyond `color-scheme/gtk-theme/icon-theme` to include everything the session touches (`cursor-theme`, `text-scaling-factor`, …); (2) capture the baseline *before* the session mutates anything (persist from the prior GNOME session or a GDM/pre-session hook) — the save-at-Hyprland-start prototype races with early cursor init and captures already-changed values. Also scope the omarchy user units off generic `graphical-session.target` so they don't run under GNOME.
- **Go / no-go on Phase 1: GO.** The highest-risk, least-proven pieces of the design all pass on real Fedora 44 under SELinux enforcing: the Quickshell lock authenticates (Q2), both PAM/faillock variants behave (Q3), zero desktop-attributable AVC denials (Q4), and the unprivileged power-key inhibitor works without a polkit prompt (Q7). The session starts from GDM (Q1) and the desktop milestones work by hand (Q6). No fundamental blockers surfaced. The GNOME invariant (Q5) is the one partial: the restore mechanism is sound but needs the two fixes above — a design refinement, not a dead end. The spec/manifest corrections found along the way (drop `power-profiles-daemon` for `tuned-ppd`; add `fcitx5`; disable weak deps; scope the user units) are all straightforward Phase 1 work. Two items to carry to a bare-metal phase: suspend/resume-to-lock timing (untestable in the VM) and the dead-menu-entry audit.
